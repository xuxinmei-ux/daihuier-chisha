# 待会儿吃啥 —— 用腾讯位置服务解决「午饭吃什么」的决策内耗

![首页](./screenshots/index.png)
![结果页](./screenshots/result.png)

> 原生微信小程序：打开即定位，在附近 100/250/500 米内随机挑一家**真实**餐馆，转盘停在哪家就吃哪家，点导航直接走。

## 一、项目简介

楼下三十家店，却要在工位上纠结十分钟 —— 这个小程序就是把这段纠结压缩成**一次点击**。

授权定位 → 选半径 → 点「转！别想了」→ 点「停！就它了」→ 导航，全程不超过 5 步；半径有智能默认、排除项默认折叠，所以真正的必点操作只有一个按钮。

刻意**不做**：餐厅列表、评分、评价、图片墙、菜单、推荐理由。选择困难的人不缺信息，缺的是一个决定。

技术上：原生 WXML/WXSS/JS，不用 Taro/uni-app/React/Vue，无后端、无数据库、无登录、无 UGC、无支付；界面全部 CSS + emoji，UI 零图片资源，小程序包约 112KB。地图能力全部来自**腾讯位置服务**（微信小程序 JavaScript SDK v1.2，官方文件原样内置）。

## 二、为什么选择腾讯位置服务

1. **微信生态无缝集成**：SDK 内部直接用 `wx.request` 发请求，不用自己拼 URL、不用处理 JSONP 与签名，放一个 38KB 的文件进工程就能搜周边。
2. **GCJ-02 原生支持**：`wx.getLocation` 返回的就是 GCJ-02，腾讯位置服务用同一套坐标系，坐标拿到就能用；换数据源时哪怕几十米的偏差，也足以把「楼下那家面馆」搜成隔壁街。
3. **SDK 与场景对齐**：`qqmapsdk.search()` 支持 `nearby` 圆形检索、按距离排序与分类过滤，正好覆盖「500 米内随机挑一家」，不用更重的参数。

## 三、核心功能与技术实现

### 1. 极简决策链路（≤ 5 步）

| 步 | 动作 | 可跳过 |
|---|---|---|
| 1 | 打开，授权定位 | 否（拒绝时引导去 `wx.openSetting`） |
| 2 | 选半径 / 勾「不想吃」 | 可跳过（午高峰默认 100m，其余 500m） |
| 3 | 点「转！别想了」 | 否 |
| 4 | 点「停！就它了」 | 否 |
| 5 | 结果页点「导航去这里」 | 否 |

### 2. POI 检索与过滤管线

```js
qqmapsdk.search({
  keyword: '美食',
  location: { latitude, longitude },   // 腾讯：纬度在前、经度在后
  distance: '500',                     // 半径，单位米
  auto_extend: '0',                    // 必须是字符串，见第四节
  page_size: 20, page_index: 1,        // 腾讯单页上限 20
  success: res => console.log(res.data) // 每家带 _distance、address_reference
});
```

拿到原始 POI 后统一归一化，再走四道过滤：

- **距离**：优先用接口的 `_distance`（米），缺失时用 haversine 自算兜底；
- **地址**：`address` 为空则退到 `address_reference.landmark_l2.title`（腾讯常给「越华路口」这类地标），再退「地址暂缺」，卡片不会开天窗；
- **去重**：店名相同 **或** 相距 60 米内视为同一家 —— 同一家店常以「xx店」「xx分店」重复出现；
- **排除过滤**：把平台 `category` 拍平后做 token 匹配，命中用户勾选的类别就剔除；已保存的排除项在客户端再过一遍，作为最后一道防线。

### 3. 算法兜底：不足 4 家就换关键词补搜

只搜「美食」时周边可能只返回两三家（POI 本身稀疏）。过滤后若不足 4 家，就用**未被排除的类别关键词**（面食、快餐、火锅等）逐个补搜，每类取 10 条，合并 → 去重 → 再过滤 → 客户端按距离升序。

这样即使一个人把 10 类排除掉 6 类，仍有 4 个关键词在工作，不会直接掉进空状态。

## 四、踩坑与实战经验

### 坑 1：`auto_extend` 传数字 `0` 会被吞掉（最容易踩）

SDK 源码里写的是：

```js
var auto_extend = options.auto_extend || 1;
```

传数字 `0` 时 `0 || 1` 得 **1**，请求串变成 `nearby(lat,lng,500,1)` —— 腾讯会把范围**自动外扩**到 1km、2km 甚至全城。用户明明选了「100m，只吃眼皮子底下的」，结果被推送到三公里外。

正确写法是传字符串 `'0'`（非空字符串为真值），请求串才是 `nearby(lat,lng,500,0)`；我们用单测精确断言这个字符串，防止升级 SDK 时回归。

### 坑 2：`category` 是冒号串，按高德的分号匹配会全盘失效

腾讯形如 `美食:中餐厅:其它中餐厅`、`美食:西餐:牛排`、`美食:小吃快餐`；高德是 `餐饮服务;中餐厅;面馆`。沿用分号切分，一条都匹配不上，排除功能等于没做。

做法是先拍平再匹配：把 `; : ： | / 、 , ，` 统一换成空格，再按「专属优先」顺序找 token（日料 → 西餐 → 火锅 → 烧烤 → 咖啡奶茶 → 甜品 → 面食 → 快餐 → 米饭 → 小吃），避免「西餐厅」被「中餐厅」这个泛 token 抢走；认不出的 `美食:中餐厅` 再用泛类目兜底归为米饭类，让「不想吃米饭」对普通中餐馆也生效。

### 其他细节

- **空 Key 会白屏**：SDK 构造函数里 `if (!options.key) throw`，Key 为空整包打挂。本工程用哨兵值实例化，业务层再拦截并弹「先填腾讯地图 Key」的中文指引；仓库里的 Key 已替换为 `YOUR_QQMAP_KEY`。
- **`page_size` 上限 20**：比高德的 25 小，首页取满 20，补搜每类取 10。
- **没有 `infocode`**：失败回调只有 `{status, message}`，按数字码给中文对策（311 Key 不对 / 199 未开 WebServiceAPI / 121 日配额用尽 / 120 限流 / 112 IP 白名单）。

## 六、运行与配置

```
待会儿吃啥333/
├─ app.js / app.json / app.wxss
├─ pages/index · spin · result       # 首页 / 转盘 / 结果
├─ components/wheel                  # 纯 CSS conic-gradient 转盘，无 Canvas
└─ utils/
   ├─ map.js                         # 腾讯位置服务封装
   ├─ qqmap-wx-jssdk.js              # 腾讯官方 SDK v1.2
   └─ storage.js · time.js · copywriting.js · wheel.js
```

1. **申请 Key**：登录 <https://lbs.qq.com> → 控制台 → 应用管理 → 我的应用 → 添加 Key，**勾选「WebServiceAPI」**（不勾会报 status 199/311），复制后填入 `utils/map.js` 顶部的 `const KEY`（当前为占位符 `YOUR_QQMAP_KEY`，需使用者自行申请替换）。
2. **换 AppID**：用微信开发者工具导入本目录，把 `project.config.json` 里的 `touristappid` 换成自己的小程序 AppID（游客 appid 无法申请定位接口）。
3. **跑起来**：开发阶段勾「详情 → 本地设置 → 不校验合法域名」即可；上线前到小程序后台把 `https://apis.map.qq.com` 加入 request 合法域名，并申请 `wx.getLocation` 权限、完善隐私指引。
4. **数据来源**：门店 100% 来自腾讯位置服务；Key 不对或域名没放行时弹出可执行的中文指引，**绝不返回本地假数据**。
